# DONE interface direction

DONE is an operating interface for merchants and shoppers, not a generic AI dashboard. The interface should disappear into the decision the user is making.

## Merchant Studio

- **Job:** turn a public storefront into a sourced draft, then let a merchant review and approve it.
- **Visual character:** calm, precise, trustworthy, and fast to scan in a live demo.
- **Palette:** neutral white/grey surfaces with one deep forest-green accent. Green is reserved for primary actions, current progress, and verified states. Purple is not part of the product palette.
- **Structure:** one visible sequence—Import, Review, Publish. The active stage and the next human gate should always be obvious.
- **Evidence:** source links, import methods, missing facts, and the independent-demo disclosure stay close to the products they qualify.
- **Controls:** familiar fields, buttons, filters, checkboxes, progress, and an inspector drawer. Components share the same radius, border, focus, hover, disabled, and loading vocabulary.
- **Motion:** brief state feedback only. No decorative page choreography. Reduced-motion settings are respected.
- **Responsive behavior:** layouts collapse structurally. Phone views keep 44px-class primary touch targets, never introduce horizontal overflow, and never create a second page scroll behind an open inspector.

## Anti-patterns to avoid

- Decorative gradients, glass panels, floating metric cards, or unexplained colour.
- Oversized marketing headlines inside task surfaces.
- Tiny uppercase labels used as decoration.
- Invented merchant claims, hidden missing data, or an action that appears real when it is simulated.
- Multiple competing primary actions or nested scroll containers.
